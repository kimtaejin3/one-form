# 자소서 허브 — 기업별 답변 (모델 재조정)

작성일: 2026-07-25. [문항중심 재설계](자소서-허브-문항중심-재설계.md)의 **답변 재사용을 폐기**하고,
답변을 (기업 × 문항) 단위로 분리한다.

## 1. 문제

문항중심 재설계는 답변을 **문항 id 기준으로 재사용**했다. 그러나 같은 "지원동기"라도 회사마다 내용이
달라야 한다 — 재사용은 틀렸다. 특정 문항을 **특정 기업으로** 적고 저장해야 한다.

## 2. 모델

- **문항 풀 + 기업 매핑(다대다)은 유지** — 문항을 중복 없이 조회하는 이점은 그대로.
- **답변은 (기업, 문항) 슬롯 단위**로 각각 독립. 삼성-지원동기와 네이버-지원동기는 별개 답변.
- **`{회사}` 변수 제거** — 문항 prompt는 **제네릭**(회사명 없는 표현)으로, 답변은 **리터럴**(회사명 직접 작성).
  치환·삽입 버튼·미리보기 모두 제거.
- 어떤 기업도 안 쓰는 문항 = **공통 슬롯 1개**(company="공통")로 작성.

## 3. 백엔드 (`apps/backend/app/essays/`)

### 스키마 (`schemas.py`)
- `AnswerSlot{ company: str, deadline: str, content: str, status: Literal["미작성","작성 중","초안 완료"] }`
- `Question{ id, tag, prompt, char_limit, slots: list[AnswerSlot] }`  ← 답변은 슬롯에만
- `AnswerUpdate{ company: str, content: str, status: Literal[...] }`  ← 어느 기업인지 포함
- `DraftResponse{ question_id: int, draft: str }`

### 데이터 (`repository.py`)
- `_QUESTIONS`: `[{id, tag, prompt, char_limit}]` — prompt는 제네릭(예: "지원 동기를 서술하시오"). {회사} 토큰 없음.
- `_COMPANIES`: `[{name, deadline, question_ids}]` — 다대다 유지, 문항 공유·공통 문항 존재.
- `_ANSWERS`: `dict[tuple[str,int], {content,status}]` — 키 `(company, question_id)`. in-memory.
- 슬롯 생성: 문항을 쓰는 각 기업마다 슬롯 `{company, deadline, content/status(없으면 기본)}`. 아무 기업도
  안 쓰면 공통 슬롯 1개(`company="공통", deadline=""`).
- `save_answer(question_id, company, content, status)`: (company, question) 유효성 검증(그 기업이 그 문항을
  쓰는지, 또는 company=="공통") → `_ANSWERS[(company,question_id)]` 갱신.

### API (`router.py`)
- `GET /api/essays/questions` → `list[Question]`(slots 포함).
- `PUT /api/essays/questions/{question_id}/answer` (바디 `AnswerUpdate`, `response_model=Question`) →
  해당 슬롯 갱신. 없는 (기업,문항) 404.
- `POST /api/essays/draft` (바디 `{question_id}`, `response_model=DraftResponse`) 유지.

## 4. 화면

- **진행 요약**: 완료 슬롯 / 전체 슬롯(= 전체 (기업,문항) 지원서 문항 수).
- **문항별 뷰**: 유니크 문항 리스트. 각 행 = 유형 · "N개 기업" · 집계 상태(예: "2/3 기업 작성"). 클릭 →
  에디터에서 **기업 선택**(그 문항의 슬롯 기업들 = design-system Dropdown) 후 작성. 검색·유형필터·페이지네이션 유지.
- **기업별 뷰**: 회사 선택(Dropdown) → 그 회사 문항 + 그 슬롯(마감 D-day·상태·저장답변 미리보기). 클릭 →
  (그 회사, 문항) 편집. 기업 컨텍스트 고정.
- **에디터**: 컨텍스트 = (문항, 기업). 기업별=고정, 문항별=상단 기업 Dropdown으로 선택(옵션=그 문항의 기업들/공통).
  prompt(제네릭 그대로) · 답변 **리터럴** textarea · 글자수(리터럴 길이) · 저장(PUT + company) · 상태(초안 완료) ·
  AI 초안. `{회사}` 삽입·치환·미리보기 제거.

## 5. 프론트 (FSD)

- `entities/essay`: 타입 `Question`(slots, gen:api). `fillCompany`(치환) 제거.
- `features/save-answer`: PUT 바디에 `company` 포함, 슬롯 갱신.
- `pages/essays`: 선택은 (questionId, company)로. 문항별에서 기업 미선택 시 그 문항의 첫 기업 슬롯 기본.
  검색·유형·뷰·회사·페이지는 useState, 서버상태 Query, useEffect 페칭 금지.

## 6. 재사용 / 폐기

- **재사용**: design-system Dropdown·Pagination, 검색·유형필터·2뷰·진행요약(슬롯 기준으로 재계산), 저장·글자수·상태·AI초안 로직.
- **폐기**: `{회사}` 치환(fillCompany·삽입 버튼·답변 미리보기), 문항 id 기준 단일 답변.

## 7. 테스트

- **pytest**: 슬롯 생성(문항 쓰는 기업 수만큼·공통 1개), (기업,문항) 저장이 **독립**(삼성-A 저장이 네이버-A 불변),
  없는 (기업,문항) 404, status 422, draft shape.
- **vitest**: 문항별에서 문항 클릭 → 기업 선택 → 작성·저장, 기업별에서 (회사,문항) 편집, 저장 독립(한 슬롯만 갱신),
  진행이 슬롯 기준, 글자수(리터럴). {회사} 흔적 없음.

## 8. DAG

1. **backend-dev**: 슬롯 모델 + 스키마 + API + gen:api + pytest.
2. **web-dev** (deps 1): 슬롯 기반 재배선 + 문항별 기업 선택 에디터 + {회사} 제거, vitest.
3. **qa** (deps 2): lint·test·build·드리프트·요구·회귀.
4. QA 통과 → In Review → 확인 → 머지.
